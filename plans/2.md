# Implementation Plan: Execution Feasibility Ranker

## Overview

The Execution Feasibility Ranker is a **vector function** that takes an array of startup ideas (in various modalities) and produces a probability distribution representing relative execution feasibility. The output is a vector of scores summing to approximately 1, with one score per input item.

---

## Input Schema Structure

```json
{
  "type": "object",
  "description": "A collection of startup ideas to evaluate and rank by execution feasibility",
  "properties": {
    "items": {
      "type": "array",
      "description": "An array of startup ideas in various formats (text, image, audio, video, or composite)",
      "items": {
        "anyOf": [
          {
            "type": "string",
            "description": "A text pitch describing the startup idea"
          },
          {
            "type": "image",
            "description": "An image-based pitch (mockup, diagram, slide)"
          },
          {
            "type": "audio",
            "description": "An audio pitch (voice memo, recorded presentation)"
          },
          {
            "type": "video",
            "description": "A video pitch (demo, presentation recording)"
          },
          {
            "type": "array",
            "description": "A composite pitch combining multiple modalities",
            "items": {
              "anyOf": [
                {"type": "string"},
                {"type": "image"},
                {"type": "audio"},
                {"type": "video"}
              ]
            }
          }
        ]
      }
    }
  },
  "required": ["items"]
}
```

---

## Input Maps

This function requires an **input map** to enable mapped task execution over each item in the array. The input map transforms each item for individual evaluation while maintaining access to the full array for comparative ranking.

### Input Map: `item`
```json
{
  "input_maps": {
    "item": {
      "$jmespath": "input.items"
    }
  }
}
```

This map allows tasks to iterate over each startup idea individually using `$map: item` syntax.

## Task Definitions

### Task 1: Technical Feasibility Assessment (Mapped)

**Type:** `vector.completion` with `$map: item`

**Purpose:** Evaluate each idea's technical buildability.

**System Prompt:** Expert in technology readiness assessment. Evaluate whether this startup idea can be built with existing technology or requires breakthroughs. Consider: technology readiness level, existence proofs, software vs hardware vs deep science, simultaneous technical challenges. Ignore whether the idea is good—only assess if it can be BUILT.

**Responses (5-point scale):**
1. "Trivially buildable - uses only proven, production-ready technologies"
2. "Clearly buildable - requires engineering but no research breakthroughs"
3. "Probably buildable - faces technical challenges but within known physics"
4. "Difficult to build - requires significant advances or novel integration"
5. "Cannot be built - requires scientific breakthroughs not yet achieved"

**Output Expression:**
```
output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
```

---

### Task 2: Resource Requirements Assessment (Mapped)

**Type:** `vector.completion` with `$map: item`

**Purpose:** Evaluate resource assemblability for each idea.

**System Prompt:** Expert in startup resource planning. Evaluate whether this idea's required resources (capital, talent, time, materials) can be assembled by a typical startup team. Consider: minimum viable capital, founder-buildable MVPs, talent availability, proprietary inputs, time-to-revenue. Assume a small team with modest seed capital.

**Responses (5-point scale):**
1. "Bootstrappable - can start with laptop and sweat equity"
2. "Modest resources - achievable with seed funding and available talent"
3. "Significant resources - requires substantial but obtainable capital and team"
4. "Heavy resources - requires institutional capital or rare expertise"
5. "Extreme resources - requires resources beyond typical startup access"

**Output Expression:**
```
output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
```

---

### Task 3: Regulatory Complexity Assessment (Mapped)

**Type:** `vector.completion` with `$map: item`

**Purpose:** Evaluate regulatory navigability for each idea.

**System Prompt:** Expert in regulatory compliance and legal frameworks. Evaluate the regulatory and legal barriers this startup idea faces. Consider: required permits/licenses, approval timelines, legal clarity vs gray zones, compliance costs, jurisdictional variation. Rate the navigability of the regulatory landscape.

**Responses (5-point scale):**
1. "Minimal regulation - operates in permissive environment with few constraints"
2. "Light regulation - standard business licenses, well-understood compliance"
3. "Moderate regulation - significant licensing or compliance, established pathways"
4. "Heavy regulation - lengthy approvals, ongoing compliance, specialized legal needs"
5. "Extreme regulation - legal gray zone, requires reform, or faces prohibitive barriers"

**Output Expression:**
```
output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
```

---

### Task 4: Execution Risk Profile Assessment (Mapped)

**Type:** `vector.completion` with `$map: item`

**Purpose:** Evaluate path-to-market clarity for each idea.

**System Prompt:** Expert in go-to-market strategy and startup execution. Evaluate how straightforward the path from concept to customer is for this idea. Consider: customer clarity, existing channels, behavior change requirements, chicken-and-egg dynamics, network effects, sales cycle length. Rate the execution complexity.

**Responses (5-point scale):**
1. "Clear path - known customer, established channel, straightforward operations"
2. "Navigable path - identifiable customer, available channels, manageable complexity"
3. "Uncertain path - requires market discovery or novel go-to-market approach"
4. "Difficult path - multi-sided dynamics, behavior change, or long sales cycles"
5. "Treacherous path - requires ecosystem creation, network effects, or unpredictable adoption"

**Output Expression:**
```
output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
```

---

### Task 5: Holistic Feasibility Synthesis (Mapped)

**Type:** `vector.completion` with `$map: item`

**Purpose:** Synthesize all dimensions into a unified feasibility score, applying appropriate weighting based on the idea's nature.

**System Prompt:** Expert in startup feasibility assessment. Given a startup idea, provide a holistic judgment of its execution feasibility. Consider ALL dimensions: technical buildability, resource assemblability, regulatory navigability, and path-to-market clarity. Weight dimensions by what matters most for THIS specific idea (tech ventures: weight technical; service businesses: weight execution; regulated industries: weight regulatory; capital-intensive: weight resources). An idea that fails on any critical dimension is not feasible. Assess for a 5-10 year timeframe with a competent (not exceptional) team.

**User Prompt Construction:**
```
Evaluate the OVERALL EXECUTION FEASIBILITY of this startup idea:

[item content]

Consider this is the type of venture where [identify limiting factor] is most critical.
Set aside whether the idea is GOOD or PROFITABLE—only assess whether it CAN BE EXECUTED.
```

**Responses (5-point scale):**
1. "Highly feasible - all dimensions favorable, clear path to execution"
2. "Feasible - mostly favorable, manageable challenges across dimensions"
3. "Moderately feasible - significant but surmountable obstacles"
4. "Marginally feasible - serious obstacles in one or more dimensions"
5. "Not feasible - fundamental barriers prevent execution within startup constraints"

**Output Expression:**
```
output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
```

---

### Task 6: Comparative Ranking Distribution

**Type:** `vector.completion` (operates on full array)

**Purpose:** Normalize holistic scores into probability distribution.

**Approach:** This task receives all holistic scores from Task 5 and normalizes them into a probability distribution. 

**Expression for normalization:**
```starlark
# tasks[4] contains array of holistic scores from Task 5
# Softmax-style normalization to create probability distribution
scores = tasks[4]
total = sum(scores)
[s / total for s in scores]
```

**Alternative implementation:** If the function schema supports mathematical operations on arrays, use direct normalization. Otherwise, use a vector.completion task that presents all ideas simultaneously and asks for relative probability allocation.

## Expressions Required

### Input Access Expressions

1. **Item access for mapped tasks:**
   ```json
   {"$jmespath": "item"}
   ```

2. **Full array access for final ranking:**
   ```json
   {"$jmespath": "input.items"}
   ```

### Output Transformation Expressions

1. **5-point scale to 0-1 score:**
   ```starlark
   output['scores'][0] * 1.0 + output['scores'][1] * 0.75 + output['scores'][2] * 0.5 + output['scores'][3] * 0.25 + output['scores'][4] * 0.0
   ```

2. **Array normalization (probability distribution):**
   ```starlark
   # Assuming tasks[4] is array of holistic scores
   total = sum([tasks[0][i] + tasks[1][i] + tasks[2][i] + tasks[3][i] + tasks[4][i] for i in range(len(tasks[4]))])
   # Or simpler: normalize tasks[4] directly
   [s / sum(tasks[4]) for s in tasks[4]]
   ```

3. **Final output construction:**
   ```starlark
   # Output vector matching input array length
   tasks[5]  # or the normalized array from the final task
   ```

## Implementation Notes

### Task Dependencies

- Tasks 1-4 can run in parallel (independent dimension assessments)
- Task 5 depends on Tasks 1-4 (synthesis requires all dimensions)
- Task 6 depends on Task 5 (normalization requires holistic scores)

### Normalization Strategy

The final normalization should use softmax-style conversion to ensure:
1. All scores are positive
2. Scores sum to approximately 1
3. Relative differences are preserved
4. Extreme scores don't dominate unfairly

```starlark
# Simple normalization
scores = [task5_score_for_each_item]
total = sum(scores)
normalized = [s / total for s in scores]
```

### Handling Edge Cases

1. **Single item:** Output should be [1.0]
2. **All equal scores:** Output should be [1/n, 1/n, ..., 1/n]
3. **One extreme outlier:** Should still get meaningful (if small) probability mass
4. **Empty array:** Should return empty array []

### Presentation Quality Filter

All prompts must emphasize:
- "Ignore presentation quality, production values, and polish"
- "A poorly recorded pitch for a feasible idea outranks a slick pitch for an impossible idea"
- "Extract the core concept and assess only the underlying execution challenge"
